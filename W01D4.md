## 2. How CSS reaches the page, and the one reset rule — what and why (~15 min)

CSS lives in its own file and the HTML pulls it in with a `<link>`. Create
`src/styles.css` (empty for now) and add this line inside `<head>`, below the
`<title>`:

```html
<link rel="stylesheet" href="styles.css">
```

`href="styles.css"` is a **relative** path — "a file called styles.css next to this
HTML file." Keep paths relative; an absolute `/styles.css` will break when you deploy
on Day 5 of Week 2.

Now the first rule. Type this at the top of `styles.css`:

```css
*, *::before, *::after { box-sizing: border-box; }

body {
  margin: 0;
  font-family: system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
}
```

- `box-sizing: border-box` on `*` (every element) — changes what `width` means. By
  default, if you set `width: 200px` and then add `padding: 20px`, the visible box is
  **240px** wide (width = content only; padding and border are added on top). With
  `border-box`, that same element is **200px** wide and the padding eats inward. It is
  far easier to reason about, and nearly every real stylesheet sets it globally on the
  first line.
- `margin: 0` on `body` — browsers add ~8px of margin around the body by default;
  clear it so your layout starts from a known zero.
- `font-family: system-ui, ...` — use whatever clean UI font the operating system
  ships (San Francisco on Mac, Segoe on Windows). No font download, no layout shift.

Save, reload. The heading font changes very slightly and the page hugs the top-left
corner. Small, but it means the file is wired up.

## 3. Layout: the column (~25 min)

Add to `styles.css`:

```css
body {
  max-width: 28rem;
  margin: 2rem auto;
  padding: 0 1rem;
  line-height: 1.5;
}

#new-task {
  display: flex;
  gap: 0.5rem;
  margin-bottom: 1rem;
}

#task-input {
  flex: 1;
  padding: 0.5rem;
}
```

- `max-width: 28rem` + `margin: ... auto` — cap the content width and centre it.
  `auto` left/right margins split the leftover space evenly, which is the standard
  centring trick for a block with a max width.
- `#new-task { display: flex }` — lay the label, input, and button out in a **row**
  instead of stacked. `gap: 0.5rem` puts space between them without margins.
- `#task-input { flex: 1 }` — "take all the leftover horizontal space in the row." The
  input grows; the label and button stay their natural size.

Save, reload. The form is now one tidy row, centred, with the input stretching to fill
it.

## 4. The list rows: flexbox again (~25 min)

```css
#list {
  list-style: none;
  padding: 0;
  margin: 0;
}

#list li {
  display: flex;
  align-items: center;
  gap: 0.5rem;
  padding: 0.5rem 0;
  border-bottom: 1px solid #ddd;
}

#list li span {
  flex: 1;
}
```

- `list-style: none; padding: 0` — kill the bullet points and the browser's default
  left indent on `<ul>`.
- `#list li { display: flex; align-items: center }` — each row is a horizontal line
  with its three children (checkbox, span, button) vertically centred.
- `#list li span { flex: 1 }` — the text span takes all the leftover width, which
  pushes the Delete button to the far right of the row.
- `border-bottom` — a hairline divider between rows.

Save, reload. The sample row is now checkbox — text — Delete, on one line, with a
divider under it.

**Break it deliberately**, then undo:

- Delete `#list li span { flex: 1 }`. Reload. The Delete button jumps left, right up
  against the text. That one line is what holds the layout apart.
- Change `align-items: center` to `align-items: flex-start`. Reload. The checkbox
  hops to the top of the row. Change it back.

## 5. The done state — it must match your sketch (~15 min)

```css
#list li.done span {
  text-decoration: line-through;
  color: #999;
}
```

This targets: a `<span>` **inside** an `<li>` that has the class `done`. Right now no
row has that class, so nothing changes.

Test it by hand: in `index.html`, temporarily change the sample row's opening tag to
`<li class="done">`. Reload — the text is struck through and grey. Compare to the
done-state row in your sketch. Adjust the CSS until it matches what you drew (maybe you
wanted it lighter, maybe no strikethrough).

**Then take `class="done"` back off** the sample row before you commit. The committed
sample row is in its normal state.

## 6. Mobile check at 360px (~10 min)

Open DevTools, click the device-toolbar icon, set the width to **360px** (a small
phone).

- The row must not cause a horizontal scrollbar. If long text pushes the Delete button
  off-screen, add `overflow-wrap: anywhere;` to `#list li span`.
- The checkbox and Delete button shouldn't be uncomfortably cramped. Nudge `padding`
  or `gap` up if they are.
- The form row should still fit. If the Add button gets squeezed, that's usually fine
  at this size, but note it.
