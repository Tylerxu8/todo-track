## 2. How CSS reaches the page, and the one reset rule — what and why (~15 min)

HTML describes *what's on the page* (a heading, a form, a list). CSS describes *how it
looks* — colors, spacing, layout. They're kept in separate files on purpose, so you
can redesign the look without touching the structure at all.

Every CSS rule has the same shape: a **selector** (which element(s) it applies to),
then curly braces containing **property: value** pairs. `body { margin: 0; }` reads
as "for the `<body>` element, set the `margin` property to `0`." You'll write dozens
of these today.

Create `src/styles.css` (empty for now). Pull it into the page by adding this line
inside `<head>`, below the `<title>`:

```html
<link rel="stylesheet" href="styles.css">
```

- `href="styles.css"` — a **relative** path: "a file called styles.css, sitting right
  next to this HTML file." Keep paths relative; an absolute `/styles.css` (starting
  with a slash) means something different once you deploy, and will break on Day 5 of
  Week 2.

Now the first rule. Type this at the top of `styles.css`:

```css
*, *::before, *::after { box-sizing: border-box; }

body {
  margin: 0;
  font-family: system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
}
```

- The selector `*` means "every single element on the page." `box-sizing: border-box`
  changes what the `width` property actually measures. By default, if you set
  `width: 200px` on a box and then add `padding: 20px` (space *inside* the box, between
  its edge and its content), the box you actually see is **240px** wide — the browser
  adds padding on top of the width you asked for. With `border-box`, that same box
  stays **200px** wide no matter what padding you add; the padding eats into the space
  you already specified instead of growing past it. It's far easier to reason about
  sizes this way, and nearly every real stylesheet turns it on globally as the very
  first rule, which is what you just did.
- `margin: 0` on `body` — browsers add a small default margin (space *outside* the
  box, between it and its neighbors) around the body automatically; clearing it means
  your layout starts from a known, exact zero instead of a hidden default.
- `font-family: system-ui, ...` — use whatever clean interface font the operating
  system already ships (San Francisco on a Mac, Segoe on Windows). No font to
  download, no text jumping around while a web font loads in.

Save, reload. The heading font changes very slightly and the page hugs the top-left
corner. Small, but it means the file is wired up.

## 3. Layout: the column (~25 min)

Add to `styles.css`:

```css
body {
  max-width: 28rem;
  margin: 2rem auto;
  padding: 0 1rem;
  line-height: 1.5;
}

#new-task {
  display: flex;
  gap: 0.5rem;
  margin-bottom: 1rem;
}

#task-input {
  flex: 1;
  padding: 0.5rem;
}
```

- `#new-task` is a selector too — the `#` means "the element whose `id` is exactly
  this," matching the `id="new-task"` you gave the form back on Day 2. CSS and HTML
  talk to each other through these `id` and `class` names.
- `max-width: 28rem` + `margin: ... auto` — cap how wide the content can get, then
  centre it. Setting the left/right margin to `auto` tells the browser "split
  whatever space is left over evenly on both sides" — the standard trick for centring
  a block that has a max width.
- `#new-task { display: flex }` — this is the single most useful layout tool you'll
  use in this project. By default, elements stack vertically, one under the next.
  `display: flex` turns that off for this element's direct children and lays them out
  in a **row** instead — the label, input, and button now sit side by side. `gap:
  0.5rem` adds even spacing between them without you having to add margin to each one
  individually.
- `#task-input { flex: 1 }` — inside a flex row, `flex: 1` on one child means "you
  take up all the leftover space, after everything else has taken what it needs." The
  input stretches to fill the row; the label and button stay their natural size.

Save, reload. The form is now one tidy row, centred, with the input stretching to fill
it.

## 4. The list rows: flexbox again (~25 min)

```css
#list {
  list-style: none;
  padding: 0;
  margin: 0;
}

#list li {
  display: flex;
  align-items: center;
  gap: 0.5rem;
  padding: 0.5rem 0;
  border-bottom: 1px solid #ddd;
}

#list li span {
  flex: 1;
}
```

- `#list li` is a selector matching "any `<li>` that's inside the element with
  `id="list"`" — a space between two selectors means "the second one, found anywhere
  inside the first," not just direct children.
- `list-style: none; padding: 0` — kill the bullet points and the browser's default
  left indent on `<ul>`, both of which are on by default and neither of which you
  want here.
- `#list li { display: flex; align-items: center }` — same row-layout trick as the
  form. `align-items: center` additionally lines everything up vertically in the
  middle of the row, so a small checkbox and a line of text don't look misaligned
  against each other.
- `#list li span { flex: 1 }` — the text span takes all the leftover width, the same
  `flex: 1` idea as the input above, which pushes the Delete button all the way to
  the far right of the row.
- `border-bottom` — a thin line under each row, one pixel wide, solid, light grey.

Save, reload. The sample row is now checkbox — text — Delete, on one line, with a
divider under it.

**Break it deliberately**, then undo:

- Delete `#list li span { flex: 1 }`. Reload. The Delete button jumps left, right up
  against the text. That one rule is what holds the layout apart.
- Change `align-items: center` to `align-items: flex-start`. Reload. The checkbox
  hops to the top of the row instead of the middle. Change it back.

## 5. The done state — it must match your sketch (~15 min)

```css
#list li.done span {
  text-decoration: line-through;
  color: #999;
}
```

Read that selector out loud: "a `<span>` that's inside an `<li>` that **also** has the
class `done`." Writing `li.done` (no space) means both conditions apply to the same
element — it's an `<li>`, *and* it carries the class `done`. Right now nothing has
that class, so this rule matches nothing yet, and nothing changes.

Test it by hand: in `index.html`, temporarily change the sample row's opening tag to
`<li class="done">`. Reload — the text is struck through and grey. Compare to the
done-state row in your sketch. Adjust the CSS until it matches what you drew (maybe you
wanted it lighter, maybe no strikethrough).

**Then take `class="done"` back off** the sample row before you commit. The committed
sample row is in its normal state.

## 6. Mobile check at 360px (~10 min)

Open DevTools, click the device-toolbar icon, set the width to **360px** (a small
phone).

- The row must not cause a horizontal scrollbar. If long text pushes the Delete button
  off-screen, add `overflow-wrap: anywhere;` to `#list li span`.
- The checkbox and Delete button shouldn't be uncomfortably cramped. Nudge `padding`
  or `gap` up if they are.
