# W01D4 — CSS: layout, the list, the done state

**Goal:** the app looks intentional. A centered column, a readable list, a clear
*done* style, and nothing broken on a phone-width screen.

**Time budget:** ~90 min hands-on · ~15 min journal · ~15 min buffer

> Still AI-free. Reference: [MDN — CSS first
> steps](https://developer.mozilla.org/en-US/docs/Learn/CSS/First_steps).

---

## 1. Wire up the stylesheet (~10 min)

Create `src/styles.css`. Link it from `<head>`:

```html
<link rel="stylesheet" href="styles.css">
```

Start the file with a reset you'll want everywhere:

```css
*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; font-family: system-ui, -apple-system, Segoe UI, Roboto, sans-serif; }
```

## 2. Layout (~30 min)

Center the app in a single column, capped width, breathing room:

```css
body {
  max-width: 28rem;
  margin: 2rem auto;
  padding: 0 1rem;
  line-height: 1.5;
}
#new-task {
  display: flex;
  gap: 0.5rem;
  margin-bottom: 1rem;
}
#task-input { flex: 1; padding: 0.5rem; }
```

## 3. The list (~25 min)

Strip the bullets, space the rows, make each row a flex line: checkbox, text that
takes the remaining width, delete button pushed to the end.

```css
#list { list-style: none; padding: 0; margin: 0; }
#list li {
  display: flex;
  align-items: center;
  gap: 0.5rem;
  padding: 0.5rem 0;
  border-bottom: 1px solid #ddd;
}
#list li span { flex: 1; }
```

## 4. The done state (~20 min)

A `.done` class on the `<li>` that strikes through and greys the text:

```css
#list li.done span {
  text-decoration: line-through;
  color: #999;
}
```

Add `class="done"` to your temporary sample `<li>` to see it. Take it back off before
you commit — the sample row should be in its normal state.

## 5. Mobile (~10 min)

Open DevTools, set the viewport to 360px wide.

- The row must not overflow horizontally. If long task text pushes the delete button
  off-screen, add `overflow-wrap: anywhere;` to `#list li span`.
- Tap targets (checkbox, delete) shouldn't be cramped. Bump padding if they are.

> **Foundations note — the box model.** Every element is a box: content, then
> `padding`, then `border`, then `margin`. By default `width` sizes only the content,
> so padding and border make the visible box *wider* than the number you set. The
> `box-sizing: border-box` rule at the top of the file changes that so `width`
> includes padding and border — far easier to reason about.

---

## What "done" looks like for W01D4

- App is a centered column, max width ~28rem.
- The sample row shows checkbox, text, and delete on one line, with a divider.
- Adding `class="done"` to a row strikes it through and greys it; removed before
  commit.
- No horizontal scroll at 360px wide.
