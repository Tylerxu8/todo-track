# W01D3 — Foundations: semantic HTML and the DOM tree

**No code. No AI.** Reading, one paper exercise, one self-quiz. No commit required
beyond the journal entry. No review.

**Time budget:** ~45 min reading · ~40 min exercise + quiz · ~35 min buffer

---

## Read (~45 min)

1. `sidelines/dom-tree.md` in this repo.
2. [MDN — Introduction to the
   DOM](https://developer.mozilla.org/en-US/docs/Web/API/Document_Object_Model/Introduction).
3. [MDN — HTML element
   reference](https://developer.mozilla.org/en-US/docs/Web/HTML/Element), skim; read
   the entries for `<ul>`, `<li>`, `<form>`, `<label>`, `<input>`, `<button>`.

## Exercise (~20 min)

On paper, draw the DOM tree of your own `src/index.html` as it stands after `W01D2`.

- Every element is a node. Nesting is the parent/child relationship — draw it as
  branches.
- Include the text nodes: the text "Todo" inside the `<h1>`, "New task" inside the
  `<label>`, "Buy milk" inside the `<span>`.
- Circle the node that new `<li>` elements will be added *into* on `W01D5`. (It's
  `<ul id="list">`.)
- Mark which node is the *parent* of the `<input id="task-input">`. (It's the
  `<form>`.)

## Self-quiz (~20 min)

Write your answers in `journal/J03.md`. Check them against the reading afterwards.

1. What is the parent node of `<input id="task-input">`?
2. `document.querySelector('#list')` returns what kind of value?
3. If you `appendChild` a new `<li>` to `#list`, does it become the first child or the
   last child?
4. What is the difference between an *element node* and a *text node*?
5. Why does `<label for="task-input">` need the input to carry `id="task-input"` and
   not, say, `name="task"`?
