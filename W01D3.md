# Week 1, Day 3 — Foundations: the DOM Tree (no code, no AI)
*v1.0.0*

**Goal for today:** understand what the browser turns your HTML *into*, because from
Day 5 on you stop editing HTML and start changing that thing with JavaScript. No app
code today. **No AI today** — not for reading help, not for the quiz. This is a
build-your-own-understanding day, and it has a mini-quiz instead of a mentor.

**Time budget:** ~40 min reading, ~40 min exercise + quiz, ~40 min slack.

---

## 1. Warm-up (~10 min)

- `cd ~/dev/todo-track`, `git status`. Commit yesterday's journal if it's still
  untracked: `git add journal/ && git commit -m "W01D2 journal"`.
- Open `src/index.html` in the browser. Form + one sample row, unstyled.
- Open DevTools (Cmd-Option-I) and click the **Elements** tab. That tree of
  expandable tags is today's entire topic. Leave it open.

## 2. Read (~40 min)

In this order:

1. `sidelines/dom-tree.md` in this repo. Read it twice.
2. [MDN — Introduction to the
   DOM](https://developer.mozilla.org/en-US/docs/Web/API/Document_Object_Model/Introduction).
   Read the first three sections.
3. Back in DevTools → Elements, expand every node of your own page. Click the `<span>`
   containing "Buy milk." Notice the panel shows it has a child that is just text.

The one idea to hold onto: **the browser reads your HTML file once, builds a tree of
objects from it, and then forgets the file.** Everything after that — CSS styling,
JavaScript changes — operates on the tree. When JavaScript adds a task row on Day 5,
it adds a node to the tree, and the screen updates because the screen is a rendering
of the tree.

## 3. Exercise — draw your own tree (~20 min)

On paper. Don't use DevTools for this part — draw it from your HTML, *then* check.

Draw the DOM tree of `src/index.html` as it stands after Day 2. Rules:

- Every tag is a box (a node). Draw a line from each parent down to each child.
- Nesting in the HTML = parent/child in the tree. `<body>` is the parent of `<h1>`,
  `<form>`, and `<ul>`.
- Include **text nodes**: "Todo" is a child node of `<h1>`. "New task" is a child of
  `<label>`. "Buy milk" is a child of `<span>`. Draw those as leaf boxes labelled
  `text: "Todo"` and so on.
- When done, open DevTools → Elements and compare. Fix your drawing where it's wrong,
  in a different colour.

Then annotate:

- Circle the node that new `<li>` elements get added *into* on Day 5. (It's
  `<ul id="list">`.)
- Draw an arrow to the parent of `<input id="task-input">`. (It's `<form>`, not
  `<body>`.)
- Put a star on every text node.

Photograph it → `journal/dom-tree.jpg`.

## 4. Self-quiz (~20 min)

Write answers in `journal/W01D3.md` **from memory first**. Then check them against the
reading and correct in another colour.

1. What is the parent node of `<input id="task-input">`?
2. `document.querySelector('#list')` returns what kind of value — a string, a number,
   an element node, or a list?
3. If you `appendChild` a new `<li>` onto `#list`, does it become the first child or
   the last child of `#list`?
4. `<span>Buy milk</span>` — how many nodes is that, and what kind is each?
5. Why does `<label for="task-input">` need the input to have `id="task-input"`
   specifically, rather than `name="task"`?
6. In one sentence: if the browser forgets the HTML file after parsing it, how does
   the page change when JavaScript runs?
