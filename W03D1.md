## 2. Why "grouped list" — what and why (~10 min)

Open the Reminders app (or picture it): the list of tasks doesn't touch the screen
edges. It floats as a white rounded card on a light grey background, and the line
between two tasks doesn't span the full width — it starts after the checkbox, not
at the left edge. That inset divider is the single most recognizable detail of the
iOS list style.

You'll build both pieces: the card, and the inset divider.

## 3. The card (~20 min)

In `styles.css`, change the page background and give `#list` a card treatment:

```css
body {
  background: #f2f2f7;
}

#list {
  background: white;
  border-radius: 10px;
  overflow: hidden;
  margin: 1rem 0 0;
}
```

- `background: #f2f2f7` on `body` — the grey iOS Settings/Reminders background.
- `overflow: hidden` on `#list` — without it, the rounded corners you just set would
  be visually clipped-off by the first and last row's own square corners. Hidden
  overflow forces the rows to be cropped to the rounded shape instead.

Reload. You now have a white rounded box, but the divider still spans full width and
there's a stray bottom border after the last row. Fix both:

```css
#list li {
  border-bottom: none;   /* remove the old full-width divider */
  position: relative;
}

#list li::after {
  content: "";
  position: absolute;
  left: 3rem;
  right: 0;
  bottom: 0;
  border-bottom: 1px solid #e5e5ea;
}

#list li:last-child::after {
  display: none;
}
```

- `position: relative` on the row, `position: absolute` on `::after` — the
  pseudo-element positions itself relative to its row, not the page.
- `left: 3rem; right: 0` — the divider starts 3rem in (about where the checkbox
  ends) and runs to the far right. That gap on the left is the "inset" look.
- `:last-child::after { display: none; }` — no divider under the last row; the card's
  own bottom edge closes it off.

Reload. Add a few tasks — the divider should now start after the checkbox and the
last row should have no line under it.

## 4. Custom checkbox — what and why (~15 min)

A native `<input type="checkbox">` looks like whatever the OS/browser draws — square,
grey, not the blue-filled circle Reminders uses. You can't restyle a native
checkbox's shape directly with CSS. The standard technique: keep the real checkbox
for its behavior and accessibility, but make it **invisible** (not `display: none` —
that would remove it from keyboard tab order and screen readers), and draw a sibling
element that changes appearance based on the checkbox's `:checked` state.

## 5. Change the row shape in `app.js` (~15 min)

In your `render()` function, find where you build the checkbox:

```js
const checkbox = document.createElement("input");
checkbox.type = "checkbox";
checkbox.checked = task.done;
```

Wrap it in a label with a visual circle, replacing that block with:

```js
const checkWrap = document.createElement("label");
checkWrap.className = "check";

const checkbox = document.createElement("input");
checkbox.type = "checkbox";
checkbox.checked = task.done;

const circle = document.createElement("span");
circle.className = "check-circle";

checkWrap.append(checkbox, circle);
```

Then change the line that assembles the row — find:

```js
li.append(checkbox, span, del);
```

and change it to:

```js
li.append(checkWrap, span, del);
```

- The order inside `checkWrap` — `checkbox` first, then `circle` — matters. CSS's
  `+` sibling selector only looks **forward**, so `.check-circle` can react to the
  checkbox's state only if the checkbox comes first in the markup.
- Wrapping both in a `<label>` (with no `for`/`id` needed, since the input is a
  direct child) makes clicking anywhere in the circle's area toggle the checkbox —
  exactly like a native checkbox's hit area, just bigger and round.

Save, reload. It looks unstyled right now — a checkbox next to a small nothing.
That's expected; the CSS is next.

## 6. Style the custom checkbox (~15 min)

```css
.check {
  position: relative;
  display: inline-flex;
  width: 1.5rem;
  height: 1.5rem;
  flex-shrink: 0;
}

.check input {
  position: absolute;
  inset: 0;
  opacity: 0;
  margin: 0;
  cursor: pointer;
}

.check-circle {
  width: 100%;
  height: 100%;
  border: 2px solid #c7c7cc;
  border-radius: 50%;
  transition: background-color 0.15s, border-color 0.15s;
}

.check input:checked + .check-circle {
  background-color: #007aff;
  border-color: #007aff;
}

.check input:checked + .check-circle::after {
  content: "";
  display: block;
  width: 0.35rem;
  height: 0.65rem;
  border: solid white;
  border-width: 0 2px 2px 0;
  transform: rotate(45deg);
  margin: 0.15rem auto 0 0.55rem;
}

.check input:focus-visible + .check-circle {
  outline: 2px solid #007aff;
  outline-offset: 2px;
}
```

- `.check input { opacity: 0; inset: 0; }` — the real checkbox still exists, still
  covers the whole 1.5rem box, still receives clicks and Tab focus — it's just
  invisible. This is the accessible way to hide a form control: never `display: none`
  or `visibility: hidden` on the thing a keyboard or screen-reader user needs.
- `.check input:checked + .check-circle` — "when the input right before this element
  is checked, style this element." No JavaScript needed for the visual change at all
  — the browser already knows the checkbox's state; CSS just reacts to it.
- The `::after` checkmark is drawn from a plain square border, rotated 45° and
  clipped to two sides — a common pure-CSS checkmark, no image or icon font needed.
- `:focus-visible` — a visible outline appears only for keyboard focus (Tab), not for
  a mouse click. Without this, keyboard users tabbing through the list would have no
  way to see which checkbox is focused.

Reload. Click a circle — it should fill blue with a white check. Tab to one with the
keyboard — you should see a focus outline, and Space should still toggle it (that's
free, native checkbox behavior you didn't have to write).
