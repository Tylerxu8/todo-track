## 2. Why "grouped list" — what and why (~10 min)

Open the Reminders app (or picture it): the list of tasks doesn't touch the screen
edges. It floats as a white rounded card on a light grey background, and the line
between two tasks doesn't span the full width — it starts after the checkbox, not
at the left edge. That inset divider is the single most recognizable detail of the
iOS list style.

You'll build both pieces: the card, and the inset divider.

## 3. The card (~20 min)

In `styles.css`, change the page background and give `#list` a card treatment:

```css
body {
  background: #f2f2f7;
}

#list {
  background: white;
  border-radius: 10px;
  overflow: hidden;
  margin: 1rem 0 0;
}
```

- `background: #f2f2f7` on `body` — the grey iOS Settings/Reminders background.
- `border-radius: 10px` — rounds the corners of the box by 10 pixels.
- `overflow: hidden` on `#list` — normally, content that doesn't fit an element's
  shape (or corners) just pokes out past it. This property clips anything sticking
  out to the element's own shape instead — including its own rounded corners. Without
  it, the first and last row's own square corners would visually poke past the
  rounded card underneath them, ruining the effect.

Reload. You now have a white rounded box, but the divider still spans full width and
there's a stray bottom border after the last row. Fix both:

```css
#list li {
  border-bottom: none;   /* remove the old full-width divider */
  position: relative;
}

#list li::after {
  content: "";
  position: absolute;
  left: 3rem;
  right: 0;
  bottom: 0;
  border-bottom: 1px solid #e5e5ea;
}

#list li:last-child::after {
  display: none;
}
```

- `::after` is a **pseudo-element** — a small, invisible extra element CSS lets you
  attach to a real one, without adding anything to your HTML. `content: ""` is
  required to make it appear at all (an empty string is fine; you're using this one
  purely for its border, not for any text).
- `position: relative` on the row, `position: absolute` on the `::after` — an
  absolutely positioned element normally places itself relative to the whole page.
  Adding `position: relative` to its *parent* (the row) changes that anchor point to
  the row itself instead — so `left`/`right`/`bottom` below are all measured from the
  row's own edges, not the page's.
- `left: 3rem; right: 0` — the divider line starts 3rem in from the left (about where
  the checkbox ends) and runs to the row's own right edge. That gap on the left is
  the "inset" look.
- `:last-child::after { display: none; }` — a **pseudo-class** (`:last-child`)
  selects "the last element among its siblings." No divider under the very last row;
  the card's own bottom edge closes it off instead.

Reload. Add a few tasks — the divider should now start after the checkbox and the
last row should have no line under it.

## 4. Custom checkbox — what and why (~15 min)

A native `<input type="checkbox">` looks like whatever the operating system draws —
typically a small grey square, not the blue-filled circle Reminders uses. You can't
directly restyle a native checkbox's *shape* with CSS; browsers keep that appearance
locked down. The standard workaround: keep the real checkbox for its behavior and
accessibility (it still receives clicks and can be reached by keyboard), but make it
**invisible**, and draw a separate element next to it that changes its own appearance
based on whether that (now-invisible) checkbox is ticked.

## 5. Change the row shape in `app.js` (~15 min)

In your `render()` function, find where you build the checkbox:

```js
const checkbox = document.createElement("input");
checkbox.type = "checkbox";
checkbox.checked = task.done;
```

Wrap it in a label with a visual circle, replacing that block with:

```js
const checkWrap = document.createElement("label");
checkWrap.className = "check";

const checkbox = document.createElement("input");
checkbox.type = "checkbox";
checkbox.checked = task.done;

const circle = document.createElement("span");
circle.className = "check-circle";

checkWrap.append(checkbox, circle);
```

Then change the line that assembles the row — find:

```js
li.append(checkbox, span, del);
```

and change it to:

```js
li.append(checkWrap, span, del);
```

- The order inside `checkWrap` — `checkbox` first, then `circle` — matters, and the
  reason is entirely in the CSS you're about to write: a certain kind of CSS selector
  can only look **forward** to elements that come *after* the one it's matching, never
  backward. So `.check-circle` can only react to the checkbox's state if the checkbox
  is written before it.
- Wrapping both in a `<label>` (with no `for`/`id` needed this time, since the input
  is now a direct child rather than somewhere else on the page) makes clicking
  *anywhere* inside the label — the checkbox or the circle — toggle the checkbox.
  That's exactly how a native checkbox with its own visible label behaves; you're
  just making the "label" a big round shape instead of text.

Save, reload. It looks unstyled right now — a checkbox next to a small nothing.
That's expected; the CSS is next.

## 6. Style the custom checkbox (~15 min)

```css
.check {
  position: relative;
  display: inline-flex;
  width: 1.5rem;
  height: 1.5rem;
  flex-shrink: 0;
}

.check input {
  position: absolute;
  inset: 0;
  opacity: 0;
  margin: 0;
  cursor: pointer;
}

.check-circle {
  width: 100%;
  height: 100%;
  border: 2px solid #c7c7cc;
  border-radius: 50%;
  transition: background-color 0.15s, border-color 0.15s;
}

.check input:checked + .check-circle {
  background-color: #007aff;
  border-color: #007aff;
}

.check input:checked + .check-circle::after {
  content: "";
  display: block;
  width: 0.35rem;
  height: 0.65rem;
  border: solid white;
  border-width: 0 2px 2px 0;
  transform: rotate(45deg);
  margin: 0.15rem auto 0 0.55rem;
}

.check input:focus-visible + .check-circle {
  outline: 2px solid #007aff;
  outline-offset: 2px;
}
```

- `.check input { opacity: 0; inset: 0; }` — the real checkbox still exists, still
  covers the whole 1.5rem box, still receives clicks and Tab focus — `opacity: 0`
  just makes it *invisible*, not gone. That distinction is the whole trick here: the
  browser still treats it as a fully working checkbox, it just can't be seen — the
  visible circle sitting on top of it is purely decoration.
- `.check input:checked + .check-circle` — read the `+` as "the element immediately
  after this one, as a sibling." So this rule means "when the checkbox right before
  this element is checked, apply these styles to this element." No JavaScript is
  involved in the visual change at all — the browser already tracks whether a
  checkbox is checked internally, and CSS can react to that fact directly.
- The `::after` checkmark is drawn from a plain square outline, rotated 45 degrees
  and only kept on two of its four sides (`border-width: 0 2px 2px 0` means "no
  border on top or left, 2px on right and bottom") — a common pure-CSS way to draw a
  checkmark shape without an image or an icon library.
- `:focus-visible` — a **pseudo-class** that's true only when an element has focus
  *and* the browser has decided that focus came from a keyboard, not a mouse click.
  Without this, keyboard users tabbing through the list would have no visual way to
  tell which checkbox they've currently selected.

Reload. Click a circle — it should fill blue with a white check. Tab to one with the
keyboard — you should see a focus outline, and Space should still toggle it (that's
free, native checkbox behavior you didn't have to write).

## 7. Break it deliberately (~5 min)

- Change `opacity: 0` to `display: none` on `.check input`. Reload, try to Tab to a
  checkbox. It's skipped entirely — unreachable by keyboard, because `display: none`
  removes an element from the page's interaction entirely, not just visually. Put
  `opacity: 0` back.
- Swap the order inside `checkWrap.append(...)` to `circle, checkbox`. Reload, click a
  task. The circle no longer changes — the `+` selector needs the checkbox
  *immediately before* it in the markup, and now it isn't. Put the order back.
