# Week 2, Day 2 — Refactor: Hold the List in a `tasks` Array
*v1.0.0*

**Goal for today:** the app stops reading its state from the page. One array,
`tasks`, becomes the single source of truth. Every action changes the array, then one
`render()` function rebuilds the list from it. The behaviour won't change at all —
what changes is that the data now exists as data, which is what tomorrow's
`localStorage` needs.

**Time budget:** ~90 min hands-on, ~15 min journal, ~15 min slack.

## 2. Why refactor now — what and why (~15 min)

Right now, if you asked the app "what tasks exist?", the only way to answer is to read
the `<li>` elements. "Is this one done?" is answered by checking for a CSS class.
The DOM *is* your database.

That's fine for three features. It falls apart on the fourth, and tomorrow you need
three things it can't give you:

- **Save to `localStorage`** needs the tasks as a value you can `JSON.stringify` — not
  as HTML.
- **A "2 done" counter** needs to be derived from the list and stay in sync — awkward
  when the list only exists as DOM.
- **Loading saved tasks on startup** needs to turn data back into rows — which means
  you need a function that builds rows from data anyway.

So today you build that function, `render()`, and make it the *only* thing that ever
writes to the list.

Read `sidelines/state-vs-dom.md` now.

## 3. Add the state and the renderer — type it (~30 min)

At the **top** of `app.js`, just under the three `const` element lookups:

```js
let tasks = [];
let nextId = 1;

function render() {
  list.innerHTML = "";

  for (const task of tasks) {
    const li = document.createElement("li");
    li.dataset.id = task.id;
    if (task.done) li.classList.add("done");

    const checkbox = document.createElement("input");
    checkbox.type = "checkbox";
    checkbox.checked = task.done;

    const span = document.createElement("span");
    span.textContent = task.text;

    const del = document.createElement("button");
    del.type = "button";
    del.className = "delete";
    del.textContent = "Delete";

    li.append(checkbox, span, del);
    list.appendChild(li);
  }
}
```

Every line:

- `let tasks = []` — the array of `{ id, text, done }` objects from your data model.
  `let`, not `const`, because the delete step will reassign it.
- `let nextId = 1` — the id to hand the next new task. It only ever goes up.
- `render()` — rebuilds the whole list from `tasks`, every time it's called.
- `list.innerHTML = ""` — empty the `<ul>` completely. Then rebuild from scratch. For
  a to-do list this "clear and redraw everything" is cheap and simple; you don't
  optimise it.
- `li.dataset.id = task.id` — sets `data-id="3"` on the element. This is the thread
  back from a clicked row to its task object — you'll read `li.dataset.id` in the
  handlers.
- `checkbox.checked = task.done` — the checkbox's ticked state now comes *from the
  data*, so after a rebuild it still shows correctly.
- `if (task.done) li.classList.add("done")` — same for the row's strikethrough style.

## 4. Rewrite the three handlers to go through state — type it (~35 min)

Now every handler does the same two steps: **change `tasks`, then call `render()`.**
None of them touch the DOM directly any more.

**Add** — in the submit handler, replace everything from `const li = ...` down to
`list.appendChild(li);` with:

```js
  tasks.push({ id: nextId, text, done: false });
  nextId += 1;
  render();
```

(Keep `event.preventDefault()`, the `trim()`, the empty guard, and the
`input.value = ""` / `input.focus()` lines.)

**Toggle and delete** — replace the body of the `list` click listener with:

```js
list.addEventListener("click", (event) => {
  const li = event.target.closest("li");
  if (!li) return;

  const id = Number(li.dataset.id);

  if (event.target.matches('input[type="checkbox"]')) {
    const task = tasks.find((t) => t.id === id);
    task.done = !task.done;
    render();
  }

  if (event.target.matches("button.delete")) {
    tasks = tasks.filter((t) => t.id !== id);
    render();
  }
});
```

- `Number(li.dataset.id)` — `dataset` values are always strings (`"3"`); your task
  ids are numbers (`3`). Convert, or `===` will never match.
- `tasks.find((t) => t.id === id)` — return the one task object whose id matches.
- `task.done = !task.done` — flip it. `render()` redraws it struck-through or not.
- `tasks = tasks.filter((t) => t.id !== id)` — a new array containing every task
  *except* the one with this id. Reassigns `tasks` — that's why it was `let`.

Finally, at the very bottom of `app.js`, add one line so the (empty) list renders on
first load:

```js
render();
```
