## Exercise — find the pure functions hiding in your app (~20 min)

Open `src/app.js`. Right now "add a task" is tangled up with `render()` and the DOM. A
*pure* function would just be: given the current list and some text, return the **new
list** — touching nothing else, changing nothing in place.

On paper, write the signatures and bodies for three pure functions. Don't put them in
the app yet — that's `W02D5`.

```
addTask(tasks, text, id)   -> a NEW array with one more task on the end
toggle(tasks, id)          -> a NEW array where the matching task's done is flipped
remove(tasks, id)          -> a NEW array without the task that has that id
```

Rules: no `document`, no `render()`, no `push` on the argument, no reassigning the
argument's contents. Use `[...tasks, newTask]`, `.map`, `.filter`.

## Self-quiz (~20 min)

Answers in `journal/J08.md`, then check them.

1. `JSON.stringify(tasks)` returns a value of what type?
2. `JSON.parse(text)` returns what type, given valid input?
3. A task is `{ id: 1, text: "a", done: false }`. After
   `JSON.parse(JSON.stringify(task))`, is `done` still there and still `false`?
4. What does `JSON.parse('not json at all')` do?
5. Why is a pure `addTask(tasks, text, id)` easier to unit-test than your current
   submit handler?
