## 2. Read (~40 min)

1. `sidelines/pure-functions.md` in this repo. Read it twice.
2. [MDN —
   `JSON.stringify`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/stringify)
   and
   [`JSON.parse`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/parse).
   Read the intro and the first example of each.

The two ideas, in plain terms:

- A **pure function** is like a vending machine: you put in a specific combination
  (say, 75 cents and B4), and it always gives back exactly the same snack for that
  exact combination, every single time, and nothing else in the world changes because
  you used it — the machine doesn't rearrange the other snacks, doesn't remember you
  were there, doesn't affect the vending machine down the hall. In code terms: a pure
  function takes its inputs as arguments, hands back a result, and **changes nothing
  else** — no touching the page, no touching `localStorage`, no changing the array it
  was handed. Same inputs, always the same output, every time, guaranteed. That
  guarantee is what makes a pure function so easy to test: you don't need a browser,
  a page, or any setup — you just hand it an input and check what comes back.
- **JSON** is a plain-text way of writing down data — objects and arrays — so it can
  be saved to a file, sent over the internet, or (as you'll do tomorrow) stored by the
  browser. `JSON.stringify(value)` turns a real array/object living in your program
  into a plain string of text that *looks like* JavaScript but is actually just
  characters, like `"[{\"id\":1}]"`. `JSON.parse(text)` reverses that: takes a string
  of JSON text and turns it back into a real, usable array/object.

## 3. Exercise — design your three operations as pure functions (~25 min)

On paper. Do **not** put these in the app — that's Day 5. Right now "add a task" in
your code is tangled up with `render()`, `nextId`, and the DOM: calling it does three
different jobs at once. Strip all that away and write just the data transformation —
the "vending machine" part, with nothing else attached.

Write out the signature and body of each, by hand:

```
addTask(tasks, text, id)
  -> returns a NEW array: every task in `tasks`, plus { id, text, done: false } on the end
  -> does NOT push onto `tasks` (pushing would change the array you were handed —
     not allowed for a pure function)
  -> hint: [...tasks, { id, text, done: false }]

toggle(tasks, id)
  -> returns a NEW array: same tasks, but the one whose id matches has done flipped
  -> does NOT modify any task object in place
  -> hint: tasks.map(t => t.id === id ? { ...t, done: !t.done } : t)

remove(tasks, id)
  -> returns a NEW array: every task except the one whose id matches
  -> hint: tasks.filter(t => t.id !== id)
```

The `hint` lines use two pieces of syntax you haven't met yet: `[...tasks, x]` (the
`...` "spreads" every item already in `tasks` out into a new array, then adds `x` on
the end — a way of saying "copy everything, plus one more," without changing the
original) and `tasks.map(...)` (a fourth array method: build a new array by running a
function on *every* item and collecting the results — here, "keep each task as-is,
unless its id matches, in which case swap in a changed copy"). You don't need to
write working code today — just sketch each function's job in your own words or
rough pseudocode, and note where you'd reach for one of these tools.

For each one, write two sentences under it: *what would make this impure?* (e.g. "if it
called `render()`", "if it did `tasks.push(...)`", "if it read from `document`").
