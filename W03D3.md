## 3. Exercise — draw the swipe as a state machine (~25 min)

On paper. This is the same kind of diagram you'd draw for a state-transition test
case in the QA lessons, applied to a UI gesture instead: a **state machine** is just a
drawing of every possible situation ("state") something can be in, plus every event
that moves it from one state to another.

Draw four states: **Idle** (row at rest, `transform: translateX(0)`), **Dragging**
(pointer is down, transition disabled, transform tracks the pointer), **Open** (row
snapped to `OPEN_X`, transition enabled), **Deleted** (row removed).

Draw the events that move between them:

- Idle → Dragging: `pointerdown` on `.row-content`
- Dragging → Open: `pointerup` where `currentX < OPEN_X / 2`
- Dragging → Idle: `pointerup` where `currentX >= OPEN_X / 2`
- Open → Deleted: click on `.delete`
- Open → Dragging: `pointerdown` again (you can re-drag an already-open row)

Now find the transition your code does **not** explicitly handle: what happens if a
row is Open and the user clicks a *different* row's checkbox, or scrolls the page?
Does the open row ever close on its own? Test it in the app. Write down what you
observe — if it stays open forever, that's a real, undesigned gap worth naming (you
don't have to fix it today).

## 4. Self-quiz (~25 min)

Answer in `journal/W03D3.md` from memory first, then check against the reading.

1. In `transition: transform 0.2s ease;`, name each of the three parts and what it
   controls.
2. Why did setting `transition: none` during the drag make the row track the pointer
   exactly, when leaving the transition on made it feel laggy?
3. What is the CSS property `pointer-events` (e.g. `pointer-events: none;`), and how
   is it a **completely different thing** from the Pointer Events **API**
   (`pointerdown`, `pointermove`, etc.) despite the similar name?
4. What specific problem does `setPointerCapture` solve? Describe it without using the
   word "capture."
5. `touch-action: pan-y` — what does it tell the browser, and what did you observe
   when you removed it on a touch-simulated view?
