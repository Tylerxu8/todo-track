## 2. What JavaScript actually is — a 5-minute grounding (~5 min)

HTML describes the page's *content*. CSS describes its *appearance*. **JavaScript is
the only one of the three that can make decisions and react to things** — it's the
part of a webpage that's actually a program, in the same sense as any app on your
phone. Everything from here on is JavaScript.

A **function** is a named, reusable block of instructions. You define it once, and it
runs — potentially many times — whenever something tells it to. Think of a function
like a recipe card: writing the recipe doesn't cook anything by itself; someone has to
actually follow it, and they can follow the same card a hundred times for a hundred
meals.

## 3. How a script attaches to the page — what and why (~10 min)

Create `src/app.js` (empty). Load it from `index.html` by adding this line inside
`<head>`, below the stylesheet link:

```html
<script src="app.js" defer></script>
```

- `src="app.js"` — again, a relative path.
- `defer` — **this matters.** Without it, a `<script>` sitting in `<head>` runs
  *immediately*, the instant the browser reads that line — which is *before* the
  browser has even gotten to `<body>` and built the form and list you wrote on Day 2.
  At that moment, if your code tried to find `#list`, it simply wouldn't exist yet,
  and your code would fail on its very first line. `defer` tells the browser:
  "download this file now, but hold off running it until the *entire* page has been
  read and built." By the time your code actually runs, every element you wrote is
  guaranteed to already exist.

Put one line in `app.js` to prove it loads:

```js
console.log("app.js loaded");
```

Save, reload, open the DevTools **Console** — a panel that shows messages your code
prints out, and any errors it hits. You should see `app.js loaded`.

## 4. Grab the three elements, and prove they aren't null (~15 min)

Replace that line with:

```js
const form = document.querySelector("#new-task");
const input = document.querySelector("#task-input");
const list = document.querySelector("#list");

console.log({ form, input, list });
```

A few new words here, all worth having solid:

- `document` is a built-in object that represents the entire page — it's how
  JavaScript reaches into the tree of elements you learned about on Day 3.
- `document.querySelector("#new-task")` is a **method call** — a method is just a
  function that belongs to a particular object, called with a dot:
  `object.methodName(...)`. This one means "search the whole page and hand me back
  the *first* element matching this CSS selector." The selector syntax (`#id`,
  `.class`) is exactly what you've been writing in `styles.css` all week — CSS
  selectors and `querySelector` both speak the same language.
- `const` declares a name for a value, one that this code will never reassign to
  something else. (You'll meet `let`, for values that *do* change, starting
  tomorrow.) These three — `form`, `input`, `list` — are handles onto elements that
  already exist on the page; you're not creating anything new yet, just grabbing a
  reference to something that's already there, the way jotting down someone's phone
  number doesn't create the person.

Save, reload, check the Console. You should see an object with three elements — none
of them `null` (JavaScript's way of saying "nothing here"). If any is `null`, your
selector string and your HTML `id` don't match; fix that before going on.

## 5. The submit handler — type it, don't paste (~40 min)

Add this below the three `const`s:

```js
form.addEventListener("submit", (event) => {
  event.preventDefault();

  const text = input.value.trim();
  if (text === "") return;

  const li = document.createElement("li");

  const checkbox = document.createElement("input");
  checkbox.type = "checkbox";

  const span = document.createElement("span");
  span.textContent = text;

  const del = document.createElement("button");
  del.type = "button";
  del.className = "delete";
  del.textContent = "Delete";

  li.append(checkbox, span, del);
  list.appendChild(li);

  input.value = "";
  input.focus();
});
```

That's a lot in one block, so walk it slowly — this is the single most important
pattern in the whole app, and you'll reuse its shape constantly.

- `form.addEventListener("submit", (event) => { ... })` — an **event listener**. In
  plain terms: "watch this element, and whenever a `submit` event happens on it, run
  this block of code." You're not running the code now — you're registering it to run
  *later*, at some future moment you can't predict exactly when. `addEventListener`
  itself is a method (see above) that belongs to every element on the page.
- The part `(event) => { ... }` is a function — the "recipe card" from earlier — but
  written without a name, because you're handing it directly to `addEventListener`
  rather than calling it yourself. This shape (`(something) => { ... }`) is called an
  **arrow function**; you'll see it everywhere from here on. Whatever's inside the
  parentheses — here, `event` — is a **parameter**: a placeholder name for whatever
  gets handed to the function when it actually runs. `addEventListener` automatically
  hands your function an **event object** describing exactly what just happened, and
  you chose to call that parameter `event`.
- `event.preventDefault()` — a method on that event object. Cancels the browser's
  automatic response to this particular event — here, the page-reload-with-a-URL
  behavior you saw on Day 2. Without this line, everything below it would still run,
  but the page would then immediately reload and throw all of it away.
- `input.value` — every text input element has a `.value` property holding whatever's
  currently typed into it. `.trim()` is a method that returns the same text with any
  leading/trailing spaces removed.
- `if (text === "") return;` — an `if` statement runs the code after it only when the
  condition is true. `return` immediately stops the function right there, running
  nothing else inside it. Put together: "if there's nothing but spaces in the box,
  stop here and add nothing." This is called a **guard clause** — a check at the top
  of a function that bails out early on bad input, so the rest of the function can
  assume the input is already fine.
- `document.createElement("li")` — makes a brand new `<li>` element, entirely in
  memory. It does **not** appear on the page yet — you've manufactured a part, but not
  installed it anywhere. This is the JavaScript equivalent of the `<li>` you typed by
  hand on Day 2, except now your code is the one writing the HTML, at the moment the
  user asks for it, instead of you typing it once in advance.
- The `checkbox`, `span`, and `del` blocks build the other three pieces the same way —
  make each element, then set its properties (`.type`, `.textContent`, `.className`)
  to configure it. `span.textContent = text` puts the user's typed text into the span
  as plain text — critically, *not* as HTML, so if someone typed `<b>hi</b>` as a
  task, it shows up as those literal characters on screen rather than being
  interpreted as bold formatting (or something worse). `del.className = "delete"`
  sets its `class` attribute — this is what Day 6's click handler will look for to
  recognize a Delete button.
- `li.append(checkbox, span, del)` — attaches all three as children of `li`, in the
  order given. `li` now exists as a small, complete tree in memory — a checkbox, a
  span, a button — but that whole tree is still floating, unattached to the actual
  page.
- `list.appendChild(li)` — **this is the moment the row actually appears.** Every
  element you built above existed only in memory until this exact line runs; the
  instant it does, `li` (and everything inside it) becomes a real child of
  `<ul id="list">`, which is already part of the page, and the browser redraws the
  screen to show it.
- `input.value = ""` then `input.focus()` — clear the box (set its value back to an
  empty string) and put the text cursor back inside it, ready for the next task.

Save, reload. Type "buy milk", press Enter. A row appears. Add three more.

## 6. Break it deliberately (~10 min)

Change one thing, reload, observe, then undo:

- Delete `event.preventDefault();`. Add a task. The page reloads and the row vanishes —
  because a form submit navigates the page, throwing away everything your JavaScript
  did, the same automatic behavior from Day 2 that nothing was cancelling. Put it
  back.
- Change `input.value.trim()` to `input.value` (no trim). Add a task that's just
  spaces. Now you get a blank-looking row. Put `.trim()` back.
- Delete `list.appendChild(li);` (but keep the `createElement` lines above it). Add a
  task. Nothing appears — you built the `<li>` in memory but never attached it to the
  page. This is the single most common "why isn't it showing up" bug in DOM code: you
  made the thing, but never installed it anywhere. Put it back.
