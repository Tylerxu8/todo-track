## 2. How a script attaches to the page — what and why (~10 min)

Create `src/app.js` (empty). Load it from `index.html` by adding this line inside
`<head>`, below the stylesheet link:

```html
<script src="app.js" defer></script>
```

- `src="app.js"` — again, a relative path.
- `defer` — **this matters.** A `<script>` in `<head>` normally runs *immediately*,
  before the browser has parsed `<body>`. At that moment `<form>` and `<ul>` don't
  exist yet, so `document.querySelector('#list')` would return `null` and your code
  would crash on line one. `defer` says "download this now, but don't run it until the
  whole HTML is parsed." Then your elements are guaranteed to exist.

Put one line in `app.js` to prove it loads:

```js
console.log("app.js loaded");
```

Save, reload, open the DevTools **Console**. You should see `app.js loaded`.

## 3. Grab the three elements, and prove they aren't null (~15 min)

Replace that line with:

```js
const form = document.querySelector("#new-task");
const input = document.querySelector("#task-input");
const list = document.querySelector("#list");

console.log({ form, input, list });
```

- `const` — these three never get reassigned (the *elements* don't change; only their
  contents will), so `const`, not `let`.
- `document.querySelector("#new-task")` — "find the first element matching the CSS
  selector `#new-task`." Returns the element node, or `null` if nothing matches.

Save, reload, check the Console. You should see an object with three elements — none
of them `null`. If any is `null`, your selector string and your HTML `id` don't match;
fix that before going on.

## 4. The submit handler — type it, don't paste (~35 min)

Add this below the three `const`s:

```js
form.addEventListener("submit", (event) => {
  event.preventDefault();

  const text = input.value.trim();
  if (text === "") return;

  const li = document.createElement("li");

  const checkbox = document.createElement("input");
  checkbox.type = "checkbox";

  const span = document.createElement("span");
  span.textContent = text;

  const del = document.createElement("button");
  del.type = "button";
  del.className = "delete";
  del.textContent = "Delete";

  li.append(checkbox, span, del);
  list.appendChild(li);

  input.value = "";
  input.focus();
});
```

Walk every line, so you could rebuild it from memory:

- `form.addEventListener("submit", (event) => { ... })` — "whenever this form is
  submitted, run this function." The function receives an **event object** describing
  what happened.
- `event.preventDefault()` — cancel the browser's built-in response to a form submit
  (the page reload you saw on Day 2). This is why the reload stops.
- `input.value` — the current text in the box. `.trim()` removes leading and trailing
  spaces.
- `if (text === "") return;` — if there's nothing but spaces, bail out and add
  nothing. A guard against empty rows.
- `document.createElement("li")` — make a brand-new `<li>` node. It exists in memory
  but is not on the page yet.
- The checkbox / span / del blocks build the same three children your sample row had.
  `span.textContent = text` puts the user's text in safely (as text, never parsed as
  HTML). `del.className = "delete"` is what Day 6's handler will look for.
- `li.append(checkbox, span, del)` — put all three children inside the `<li>`, in
  order.
- `list.appendChild(li)` — **now** the `<li>` joins the page, as the last child of
  `<ul id="list">`. The row appears.
- `input.value = ""` then `input.focus()` — clear the box and put the cursor back in
  it, ready for the next task.

Save, reload. Type "buy milk", press Enter. A row appears. Add three more.

## 5. Break it deliberately (~10 min)

Change one thing, reload, observe, then undo:

- Delete `event.preventDefault();`. Add a task. The page reloads and the row vanishes —
  because a form submit navigates the page, throwing away everything your JavaScript
  did. Put it back.
- Change `input.value.trim()` to `input.value` (no trim). Add a task that's just
  spaces. Now you get a blank-looking row. Put `.trim()` back.
- Delete `list.appendChild(li);` (but keep the `createElement` lines). Add a task.
  Nothing appears — you built the `<li>` but never attached it to the tree. This is
  the single most common "why isn't it showing up" bug. Put it back.
