# W01D1 — Setup, sketch, and the data model

**Goal:** a working repo, a paper sketch of the app, a written-down data model, and a
first commit. Nothing runs yet — today is about knowing exactly what you're going to
build.

**Time budget:** ~90 min hands-on · ~15 min journal · ~15 min buffer

> You'll use Claude heavily from Week 2. Not this week. Week 1 is you and the docs.
> The reason is the same one the main course used for its first week: you can't judge
> generated code in Week 2 if you've never made this app work yourself.

---

## 1. Make the repo (~15 min)

You already have this folder and the lesson files. Finish the setup:

```bash
cd ~/dev/todo-track
git init          # already done if you cloned/created it — harmless to re-run
```

Read `README.md` now if you haven't. It's the map for the next two weeks.

## 2. Sketch the app on paper (~20 min)

Actual paper. Draw the screen:

- A title at the top.
- A text box and an "Add" button.
- A list of tasks below it.
- One task row: the task text, a way to mark it done, a way to delete it.

Draw a second version of a row showing what *done* looks like — crossed out, greyed,
checkbox ticked, your call.

Photograph it, save as `journal/sketch.jpg`.

## 3. Write down the data model (~25 min)

Before any code, decide how the app represents a task *as data*, not as pixels.

Create `journal/data-model.md` and fill in:

- **A task is** an object. What fields does it need? At minimum: the text, whether
  it's done, and a unique id (so two tasks with the same text are still distinct).
  Write the shape:

  ```
  task = { id: <number>, text: <string>, done: <boolean> }
  ```

- **The whole list is** an array of those objects.
- **The three things a user can do:**
  1. **Add** — make a new task from typed text, `done: false`, a fresh id; put it on
     the end of the array.
  2. **Toggle** — find a task by id, flip its `done`.
  3. **Delete** — remove the task with that id from the array.

> **Foundations note — what a data model is.** The screen is a *view* of your data.
> Get the data shape right and the screen is easy. Try to keep state in the HTML
> itself — deciding whether a task is done by reading its CSS class — and every
> feature fights you. You'll feel this on `W02D2`, when you refactor toward the array.

## 4. Stub the entry point (~15 min)

Create `src/index.html` with the bare minimum, so the file exists and opens:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Todo</title>
</head>
<body>
  <h1>Todo</h1>
  <!-- the form and list arrive on W01D2 -->
</body>
</html>
```

Open it: `open src/index.html`. You should see a page with just the heading.

## 5. Commit (~10 min)

```bash
git add -A
git commit -m "W01D1: repo setup, sketch, data model"
```
