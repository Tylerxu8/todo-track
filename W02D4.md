# W02D4 — Persistence and edge cases

**Goal:** the list survives a refresh and a browser restart. And the app stops
misbehaving on bad input.

**Time budget:** ~90 min hands-on · ~15 min journal · ~15 min buffer

> Claude: explanations only. "Why wrap `JSON.parse` in try/catch here?" is fair.

---

## 1. Save on every change (~20 min)

`localStorage` stores strings under a key. After each action — at the end of
`render()` is simplest, since every action calls it — write the list:

```js
function save() {
  localStorage.setItem('todo-track', JSON.stringify(tasks));
}
```

Call `save()` at the end of `render()`.

## 2. Load on startup (~30 min)

Before the first `render()`:

```js
const saved = localStorage.getItem('todo-track');
if (saved) {
  try {
    tasks = JSON.parse(saved);
    nextId = Math.max(0, ...tasks.map(t => t.id)) + 1;
  } catch {
    tasks = [];            // stored value was corrupt — start clean
  }
}
render();
```

Be able to explain:

- **`if (saved)`** — `getItem` returns `null` on a first-ever visit; `JSON.parse(null)`
  would throw.
- **`try/catch`** — a user (or a bug) can leave junk under that key. A todo app that
  white-screens because its storage got mangled is worse than one that quietly starts
  empty.
- **`Math.max(0, ...)`** — the `0` seed matters. `Math.max()` with no arguments is
  `-Infinity`; on an empty list that would make `nextId` be `-Infinity`. The `0`
  guarantees the next id is at least `1`.

## 3. Edge cases (~40 min)

- **Empty / whitespace input** — already rejected by `if (text === '') return;` after
  `.trim()`. Confirm it still holds.
- **Very long text** — add a task of 300+ characters. Does the row hold its shape? If
  the text blows out the layout, add `overflow-wrap: anywhere;` to `#list li span` in
  the CSS.
- **A task counter** — show something like `3 tasks · 1 done` above or below the list.
  Compute it inside `render()` from `tasks`:

  ```js
  const done = tasks.filter(t => t.done).length;
  counter.textContent = `${tasks.length} tasks · ${done} done`;
  ```

  Add a `<p id="counter"></p>` to the HTML and select it at the top of `app.js`.

## 4. Test by hand (~15 min)

- Add tasks, refresh the page — still there.
- Quit the browser entirely, reopen, navigate back — still there.
- DevTools → Application → Local Storage → edit the `todo-track` value to `{{{` →
  reload. The app starts empty instead of breaking.
- The counter is correct after add, toggle, and delete.

> **Foundations note — array methods.** `tasks.filter(t => t.done)` returns a new
> array of just the done ones; `.map(t => t.id)` returns a new array of ids;
> `[...tasks]` copies. None of them change `tasks`. That "return new, don't mutate"
> habit is exactly what `W02D5`'s pure functions are built on.

---

## What "done" looks like for W02D4

- The list persists across a full browser restart.
- Corrupt storage makes the app start empty, not break.
- The counter shows the right totals after every action.
- Long task text doesn't break the row layout.
