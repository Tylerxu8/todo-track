# W02D1 — Toggle and delete, with event delegation

**Goal:** clicking a row's checkbox toggles its *done* style; clicking its delete
button removes the row. Both handled by a single listener.

**Time budget:** ~80 min hands-on · ~15 min journal · ~25 min buffer

> **Claude is now available — for explanations only.** Good questions today: "why

> later?", "what does `event.target.closest('li')` return if I click the span?"
> Do **not** ask it to write the handler. You write the handler.

## 1. Why not one listener per row (~15 min)

You could add a `click` listener to each checkbox and each button as you build the
row. Don't. Every new task means more listeners, and it scatters the logic across
your row-builder.

Instead: one listener on `#list`. Clicks on the children *bubble up* to it. You
inspect what was actually clicked and act. This is **event delegation**.

## 2. Write the listener (~40 min)

```js
list.addEventListener('click', (event) => {
  const li = event.target.closest('li');
  if (!li) return;

  if (event.target.matches('input[type="checkbox"]')) {
    li.classList.toggle('done');
  }

  if (event.target.matches('button.delete')) {
    li.remove();
  }
});
```

Before you keep it, be able to explain each line:

- `event.target` — the exact element clicked (the checkbox, or the button, or the
  span).
- `.closest('li')` — walks up from there to the nearest ancestor `<li>`. Returns
  `null` if there isn't one (e.g. you clicked padding).
- `.matches(selector)` — true if this element matches the selector. It's how you tell
  "was this the checkbox?" from "was this the delete button?".
- `.classList.toggle('done')` — adds `done` if absent, removes it if present.
- `.remove()` — detaches the `<li>` from the DOM.

## 3. Check your row-builder (~10 min)

The delete button your `W01D5` code creates must have `class="delete"`, or
`matches('button.delete')` never fires. Fix the builder if needed.

## 4. Test by hand (~15 min)

- Add four tasks. Tick the checkbox on two — they strike through.
- Untick one — it goes back to normal.
- Delete the middle task — the other three are untouched.
- Tick a task, then delete it — no error.
- Add a new task *after* deleting — still works (that's delegation earning its keep).

> **Foundations note — reference vs value.** `li.classList.toggle('done')` mutates the
> element in place; there's one `<li>` object and you changed it. Tomorrow your
> `tasks` array holds task *objects*, and the same idea bites: if two variables point
> at the same object, changing one changes "both". Keep it in mind for `W02D2`.

- No per-row listeners anywhere.
- Toggle, un-toggle, and delete all work; adding tasks afterwards still works.
