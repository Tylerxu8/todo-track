## 3. Extend the data model — what and why (~15 min)

Your task shape has been `{ id, text, done }` since `W01D1`. Add two fields:

```
task = { id, text, done, dueDate, flagged }
  dueDate: a string like "2026-09-10", or null if unset
  flagged: a boolean, false by default
```

Update `journal/data-model.md` to reflect this — the file should never fall out of
sync with what the code actually does.

The one thing to get right, and it's a genuinely important habit for any real
software project: **old saved tasks don't have these fields.** Anyone who used the
app before today has tasks sitting in `localStorage` shaped like
`{ id, text, done }` — no `dueDate` key, no `flagged` key, not even set to `null`;
the keys simply don't exist on those objects at all. `JSON.parse` won't invent them
out of nowhere. Reading `task.dueDate` on one of those old tasks gives you
`undefined` — JavaScript's way of saying "this property was never set on this
object" (subtly different from `null`, which means "this property exists, and its
value is deliberately nothing"). Every place you touch these fields today needs to
treat `undefined` the same as "unset," or old tasks will behave strangely, or crash
the app outright.

## 4. Update `todo.js` — type it (~30 min)

`addTask` needs the new fields on creation:

```js
export function addTask(tasks, text, id) {
  return [...tasks, { id, text, done: false, dueDate: null, flagged: false }];
}
```

Add two new pure functions, following the exact shape of `toggle`:

```js
export function setDueDate(tasks, id, dueDate) {
  return tasks.map((t) => (t.id === id ? { ...t, dueDate } : t));
}

export function toggleFlag(tasks, id) {
  return tasks.map((t) => (t.id === id ? { ...t, flagged: !t.flagged } : t));
}
```

Both follow `toggle`'s pattern exactly: find the matching task by id, replace it with
a new object that has one field changed (`{ ...t, dueDate }` means "copy every field
from `t`, then overwrite `dueDate` with this new value" — the same spread syntax from
`W02D3`), leave every other task untouched. That's the payoff of the pure-function
style: extending the app is "write one more function shaped like the ones you already
have," not "rewire everything."

## 5. Extend the tests (~15 min)

In `tests/test.js`, import the two new functions and add tests:

```js
test("setDueDate sets the date on the matching task only", () => {
  const start = [
    { id: 1, text: "a", done: false, dueDate: null, flagged: false },
    { id: 2, text: "b", done: false, dueDate: null, flagged: false },
  ];
  const out = setDueDate(start, 1, "2026-09-10");
  assert.equal(out[0].dueDate, "2026-09-10");
  assert.equal(out[1].dueDate, null);
});

test("toggleFlag flips flagged for the matching task only", () => {
  const start = [{ id: 1, text: "a", done: false, dueDate: null, flagged: false }];
  const out = toggleFlag(start, 1);
  assert.equal(out[0].flagged, true);
});
```

Run `node tests/test.js` — confirm the new tests pass alongside the old ones.

## 6. Build the UI (~20 min)

In `app.js`'s `render()`, after you build `span` (the task text), add a due-date
input and a flag button to each row:

```js
const dateInput = document.createElement("input");
dateInput.type = "date";
dateInput.className = "due-date";
dateInput.value = task.dueDate || "";

const isOverdue = task.dueDate && !task.done && task.dueDate < todayString();
if (isOverdue) dateInput.classList.add("overdue");

const flagBtn = document.createElement("button");
flagBtn.type = "button";
flagBtn.className = "flag";
if (task.flagged) flagBtn.classList.add("flagged");
flagBtn.textContent = "⚑";
```

- `task.dueDate || ""` — the `||` operator here means "use the left side, unless it's
  a value JavaScript treats as empty/absent (like `null`, `undefined`, or an empty
  string), in which case fall back to the right side." Both `null` (a fresh task's
  default) *and* `undefined` (an old task's missing field) count as "empty" to `||`,
  so this one line safely handles both cases at once, giving the date input a blank
  value either way — a date input renders an empty string as simply blank.
- `task.dueDate && !task.done && task.dueDate < todayString()` — `&&` means "and":
  the whole expression is only `true` if every single part is `true`. Read left to
  right, in order: first, is there a due date at all? (If `task.dueDate` is `null` or
  `undefined`, both are treated as `false` here, so `&&` stops immediately and the
  rest never even runs — no risk of comparing `undefined` to a date string.) Second,
  is the task *not* done? (a finished task isn't "overdue," no matter its date).
  Third, only if both of those passed, compare the due date against today's date.
  This ordering — checking that a value exists before you try to use it — is called a
  **guard**, the same idea as the empty-input check from Week 1.

You need `todayString()`. `YYYY-MM-DD` strings compare correctly with plain `<`
because they're zero-padded and most-significant-first (year, then month, then day) —
add near the top of `app.js`:

```js
function todayString() {
  return new Date().toISOString().slice(0, 10);
}
```

Now add the two new elements to the row and wire the row's content append:

```js
content.append(checkWrap, span, dateInput, flagBtn);
```

## 8. Handle the events (~10 min)

Two new delegated handlers on `list` — you already have this pattern from `W02D1`:

```js
list.addEventListener("change", (event) => {
  const li = event.target.closest("li");
  if (!li) return;
  const id = Number(li.dataset.id);

  if (event.target.matches(".due-date")) {
    tasks = setDueDate(tasks, id, event.target.value || null);
    render();
  }
});

list.addEventListener("click", (event) => {
  // ...your existing checkbox/delete branches...

  if (event.target.matches(".flag")) {
    const id = Number(event.target.closest("li").dataset.id);
    tasks = toggleFlag(tasks, id);
    render();
  }
});
```

- The `"change"` event fires on a date input when the user finishes picking a date —
  not on every intermediate click inside the date picker — which is the right moment
  to save.
- `event.target.value || null` — an emptied date input gives back the empty string
  `""`; `||` converts that back to `null`, so an unset date round-trips through
  `localStorage` consistently, instead of quietly turning into the string `""`
  forever the first time someone clears it.
