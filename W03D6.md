## 2. A pure `reorder` function — type it, and test it first (~20 min)

In `todo.js`:

```js
export function reorder(tasks, draggedId, targetId) {
  const dragged = tasks.find((t) => t.id === draggedId);
  const withoutDragged = tasks.filter((t) => t.id !== draggedId);
  const targetIndex = withoutDragged.findIndex((t) => t.id === targetId);

  return [
    ...withoutDragged.slice(0, targetIndex),
    dragged,
    ...withoutDragged.slice(targetIndex),
  ];
}
```

- Pull the dragged task out entirely, find where the target now sits in the
  *remaining* array, then splice the dragged task back in just before it.
- This is the whole reordering logic, and it involves no drag events, no DOM, no
  `lists` — just array manipulation on a plain `tasks` array. That's exactly why you
  test it *before* touching any drag code:

```js
test("reorder moves a task to just before the target", () => {
  const start = [
    { id: 1, text: "a" },
    { id: 2, text: "b" },
    { id: 3, text: "c" },
  ];
  const out = reorder(start, 3, 1);
  assert.deepEqual(out.map((t) => t.id), [3, 1, 2]);
});
```

Run `node tests/test.js`. If this fails, fix `reorder` now — debugging it here, with
no drag events involved, is far easier than debugging it once real pointer input is
in the mix.

## 3. Drag and Drop API — what and why (~15 min)

This is a **different** browser API from `W03D2`'s Pointer Events — HTML5 Drag and
Drop, built specifically for dragging elements (and files) around a page. It fires a
sequence of events on the dragged element and on whatever it passes over:
`dragstart` (once, on the element you start dragging), `dragover` (repeatedly, on
whatever's under the pointer), `drop` (once, on the element you release over).

The single most common gotcha: `dragover` **must** call `event.preventDefault()`, or
the browser refuses to allow a drop at all — its default behavior for `dragover` is
"this is not a valid drop target." You'll prove this to yourself in step 5.

## 4. Wire the drag handlers — type it (~25 min)

Make each row draggable. In `render()`, where you create `li`:

```js
li.draggable = true;
```

Add three new listeners on `list`:

```js
list.addEventListener("dragstart", (event) => {
  const li = event.target.closest("li");
  if (!li) return;
  event.dataTransfer.setData("text/plain", li.dataset.id);
  event.dataTransfer.effectAllowed = "move";
});

list.addEventListener("dragover", (event) => {
  event.preventDefault();
});

list.addEventListener("drop", (event) => {
  event.preventDefault();

  const targetLi = event.target.closest("li");
  if (!targetLi) return;

  const draggedId = Number(event.dataTransfer.getData("text/plain"));
  const targetId = Number(targetLi.dataset.id);
  if (draggedId === targetId) return;

  updateCurrentTasks(reorder(currentTasks(), draggedId, targetId));
  render();
  renderTabs();
});
```

- `event.dataTransfer.setData("text/plain", ...)` — Drag and Drop carries its payload
  through `dataTransfer`, not a variable you control, because a drag can end on a
  *different tab or app* (dragging a task onto a text editor, say). You store the
  dragged id as text and read it back out in `drop`.
- `event.dataTransfer.effectAllowed = "move"` — a hint to the browser for the cursor
  icon it shows during the drag (a "move" glyph rather than "copy").
- The `dragover` handler's only job is `preventDefault()` — see step 3.
- `if (draggedId === targetId) return;` — dropping a row on itself is a no-op, not an
  error.

If `updateCurrentTasks`/`currentTasks` don't exist yet (you skipped `W03D5`), replace
that line with `tasks = reorder(tasks, draggedId, targetId); render();` — the same
pattern your other handlers already use.

## 5. Break it deliberately (~10 min)

- Comment out `event.preventDefault();` inside the `dragover` handler only (leave the
  one in `drop`). Reload, try to drag a row onto another. **Nothing happens on
  drop** — the browser never considered your list a valid target. Put it back. This
  is the single most-searched Drag and Drop bug on the web, and now you've caused it
  and fixed it yourself.
- Remove the `if (draggedId === targetId) return;` guard. Drag a row a tiny amount and
  drop it back on itself. Watch the Console for errors from `reorder` trying to
  reinsert a task next to itself — depending on your exact implementation this may
  silently no-op or may misbehave. Either way, decide whether the guard is worth
  keeping (it is) and put it back.

## 6. A known, named limitation (~5 min)

HTML5 Drag and Drop is built around a mouse. On a real touchscreen, `dragstart` often
doesn't fire from a plain touch at all — you'd need a **press-and-hold** convention
and the same Pointer Events approach from `W03D2` (track `pointermove`, reorder the
DOM visually as you go) to get a Reminders-quality touch reorder. That's real work
and it's not built here — write this down as a known gap in your journal rather than
letting the mouse-only version quietly pass as "done."
